# V1 Milestone Plan

## Goal

Deliver a usable physical storage system supporting hierarchical addresses, item cataloging, operation-driven inventory movement, and printable QR identification.

## M0 — Foundation

- repository baseline;
- Java 21;
- Spring Boot;
- Maven;
- PostgreSQL;
- Docker Compose;
- Flyway;
- architecture skeleton;
- Angular;
- PO UI;
- test/build baseline.

Exit criterion:

Backend, frontend, database, migrations, tests, and builds have a reproducible green baseline.

## M1 — Address Types

Support create, read/list, update, and activate/deactivate.

## M2 — Addresses

Support create, hierarchy, parent/child relationships, list, detail, tree representation, update, and activate/deactivate.

## M3 — Item Categories

Support configurable item classification.

## M4 — Items

Support physical item registration and descriptive management.

Inventory location must not be treated as ordinary item CRUD.

## M5 — Inventory

Introduce the representation and consultation of current stored state.

Do not create arbitrary inventory mutation endpoints.

## M6 — Operation Foundation

Introduce `Operation`, `OperationLine`, operation types, lifecycle, execution contract, and transactional invariants.

## M7 — Entry

Implement:

`EXTERNAL → ADDRESS`

Successful execution updates current inventory.

## M8 — Internal Movement

Implement:

`ADDRESS → ADDRESS`

Successful execution moves current inventory while preserving operation history.

## M9 — Exit

Implement:

`ADDRESS → EXTERNAL`

Successful execution removes the corresponding stored state/quantity.

## M10 — Labels

Generate QR and printable PDF labels for items and addresses.

Support individual and batch generation.

## M11 — Frontend Workflows

Complete the Angular + PO UI workflows required to operate V1.

## M12 — Acceptance

Execute the canonical scenario:

```text
Create address hierarchy
        ↓
Register ESP32-S3
        ↓
ENTRY → Box 01
        ↓
INTERNAL_MOVEMENT → Drawer 02
        ↓
Verify current location
        ↓
Verify operation history
        ↓
Generate item QR label
        ↓
Generate address QR label
        ↓
EXIT
        ↓
Verify item is outside internal inventory
```

## V1 exclusions

Do not introduce intelligent address recommendations, scoring, environmental restrictions, compatibility policies, AI/ML, or microservices.

Those belong to later milestones.
